## 1. Model introduction

[MiniMax-H3](https://huggingface.co/MiniMaxAI/MiniMax-H3) is MiniMax's omni-modal generative system: one transformer
denoises a packed text + video + audio sequence and emits video with native stereo audio. MiniMax distilled CFG
into the checkpoint, so the official setting has **no classifier-free guidance** — the recipe is unguided
(`--diffusion-guidance-scale 1.0`). The Flow-GRPO recipe trains the **t2va** (text-to-audio-video) workflow, video
branch only — the audio stream is rolled out but not trained.

## 3. Family config

From `miles/backends/fsdp_utils/configs/h3.py`:

| Property | Value | Why |
|---|---|---|
| CFG training | Off (asserted) | CFG is distilled into the checkpoint; the forward is unguided |
| Weight sync | Any mode | Rollouts load the native **FL2VA** partition; full weights are converted to its layout by the `h3` ParamTransform in `models/diffusers/h3/weight_bridge.py` (native names, fused QKV in per-head rows, `[gate, value]` FFN), LoRA adapters (IPC or NCCL) in sgl-d's `lora_merge`. Full-weight sync relies on the rollout DiT staying resident, which miles guarantees by pinning sgl-d's `performance_mode` to `manual` (sgl-d's layerwise offload does no TP slicing on tensor updates) |
| LoRA targets | `attn.to_{q,k,v}`, `attn.to_out.0`, `ff.net.0.proj`, `ff.net.2` | Trainer pushes PEFT/diffusers names; sglang-d `lora_merge` maps and fuses QKV / swaps FFN |
| Optimizer state | `audio` allowed missing | GRPO, and SFT with `--fsdp-supervised-streams visual`, never train the audio branch |
| SFT streams | `--fsdp-flow-shift visual=...,audio=...` (asserted) | Every H3 SFT pair carries an audio stream noised on its own schedule — the target's soundtrack, or zero latents for a silent clip, which never enter the loss; `--fsdp-supervised-streams visual` keeps it out of the loss |
| Sample micro-batch | 1 (asserted) | One packed sequence per forward |
| Forced sampling params | `task=t2va`, `short_edge=768`, `conditions=[]` | 768 is the only short edge MiniMax verifies (sgl-d warns on any other value), so miles pins it and does not expose it; `task` follows `--diffusion-task`, and H3 rollout serves only `t2va` (asserted), with no conditions |

## 5. Recipe notes

SFT: the encode pool (`miles/rollout/encoder_hub/h3/`) imports the engine's own recipes
(`minimax_h3_packed_sequence`, `minimax_h3_encode_reference_video_rows`,
`minimax_h3_text_only_ids`), so cached train pairs stay bit-compatible with the engine's
rollout conditioning. Dataset clips must already sit on the serving grid (short_edge=768
canvas, 24 fps, 17n+5 frames); `--sft-offload-encoder` keeps the ~70GB encoders (text encoder + video/audio VAEs) in
host RAM outside encode bursts, and `--train-only` (required by `--loss-type sft_loss`) runs no rollout
engine, so no weights are synced.
`scripts/export_lora.py` converts any saved checkpoint into one safetensors file (+
`adapter_config.json` sidecar) directly loadable by sgl-diffusion's `--lora-path`.

H3 solves `x0 = x + sigma * v`, the opposite sign from the flow-matching convention the shared
train and rollout steps assume, so `compute_noise_pred` returns the negated velocity. Both halves
must agree: a flipped sign still produces plausible latents and trains on garbage.

`--diffusion-num-steps N` runs N DiT forwards on the engine (N + 1 sigma endpoints); `sglang-miles`
before its bump to sglang `main` (sgl-project/sglang#38671) ran N - 1.

The rollout engine needs sglang's `sglang-miles` branch, which
[Installation](/diffusion/getting-started/installation) already builds from
(`SGLANG_DIFFUSION_BRANCH`).

## 6. Reference results
### 6.1 LoRA SFT (8 GPUs)

Recipe defaults plus `--num-epoch 10` (the default is 3) on a 254-window video dataset (70 rollouts, 280 steps): the
aggregate loss is
dominated by which sigmas each 8-sample step happened to draw, so read convergence from the
per-bucket curves (`--log-loss-sigma-bucket`) instead, which trend downward.

![MiniMax H3 SFT loss](/diffusion/assets/images/h3/sft_loss.png)

### 6.2 Flow-GRPO + PickScore (2 GPUs)

Long run (`rollout_batch_size=4`, `n_samples_per_prompt=16`):

- `train/log_prob_mean_abs_diff` stays in **1.4e-5 .. 7.1e-5** (under `1e-4`).
- Eval PickScore (`eval/pickscore_val`, every 10 rollouts): **0.806 → 0.814**, peak **0.816** at rollout 59.
- Train `rollout/reward/raw_mean` sits around **~0.79** (64 samples / rollout, 32 per optimizer step; noisier than eval).

This is the batch-4 curve; it is not evidence for a larger topology, and no larger canonical H3
topology is committed yet.
